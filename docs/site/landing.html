One brain for all your coding agents

Your project's notes and the corrections you already made, kept as Markdown in your repo. A new session starts from them, whichever agent runs it.

It learns from sessions you already ran

hippo reads the agent history already on your disk. Corrections and repeated failures become proposed rules. Nothing reaches the notes until you keep it.

hippo ask has an agent already solved this?

$ hippo ask --sources-only "which database do previews use?"
[1] Check the gallery page and send me screenshots.  (session · default · tern-web)
    you: no, previews use the staging database, not production
[2] Check the gallery page and send me screenshots.  (session · work · tern-web)
    you: dont point previews at the production database again, staging only
[3] START HERE  (note)
    - **Use the staging database for previews, never production.** Run previews and manual checks…

A nightly check keeps it true

A nightly pass checks the notes against what agents actually did. A second model call with a fresh context must confirm each fix, and hippo revert undoes any of them.

Your team's agents start from the same notes

The notes are files in the repo, so git shares them. hippo init ignores what is per person. Nothing syncs live. Sharing in a team

  • notes/sharedthe brain itself
  • .hippo/packs/sharedthe passes everyone runs
  • .hippo/receipts/sharedwhy a note changed, and who reviewed it
  • .hippo/sessions/ignoredwhat your own agents did

Claude Code plugin

/plugin marketplace add VanitasCaesar1/hippo

DeepSeek Harness plugin

$dsh plugin --profile web add "github:VanitasCaesar1/hippo#v0.2.1&path:/plugins/dsh"

From source

$cargo install --locked --git https://github.com/VanitasCaesar1/hippo hippo

More on installing

Limits

  • Claude Code, Codex and DeepSeek Harness only. Codex is not given the notes automatically.
  • Used daily on macOS; Linux is tested in CI.
  • Not measured whether it makes agents better.
  • Built by one person for their own many-agent setup. v0.2.1, MIT.
