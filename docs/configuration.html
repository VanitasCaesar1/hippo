Configuration

hippo has two configuration files and one environment variable.

FileScopeWritten by
$HIPPO_HOME/config.tomlThe machine: which workspace, where transcripts are, which model, when to schedulehippo start, hippo init, hippo config
<workspace>/.hippo/hippo.tomlThe workspace: where notes are and how big the context may behippo init, hippo config

HIPPO_HOME is the machine directory. If it is unset or empty, hippo uses ~/.hippo. Besides config.toml it holds index.sqlite, ingest.lock, ingest-state.json, logs/ and model-runs/.

.hippo/hippo.toml is meant to be committed with the workspace, so a new machine that clones the workspace needs only hippo init (with no flags) to pick it up.

A value that breaks the rules below makes the file fail to load, and the command fails with the reason. hippo doctor then reports the failure as its one row.

hippo config show prints the settings, and hippo config set, unset, add and remove change one. Each prints the change and writes it only with --yes.

$HIPPO_HOME/config.toml

hippo start and hippo init write this file with every key set to its default except workspace, which a history-only setup leaves out until hippo init names one. In this file only, a leading ~ is expanded to your home directory.

KeyTypeDefaultMeaning
workspacepathnone; required for notes, context, dreaming and hooksThe one workspace every command uses. Absolute once ~ is expanded. hippo init writes the canonical path of the directory you ran it in, or of --workspace.
transcript_rootslist of glob patterns["~/.claude*/projects", "~/.codex/sessions", "~/.dsh/sessions", "~/.local/share/opencode", "~/.local/share/muse/sessions", "~/.commandcode/projects"]Where transcripts live. hippo walks every root. A *.jsonl file whose name starts with rollout- is read as a Codex rollout; a session.v<N>.jsonl or session.v<N>.jsonl.zstd in a session folder of a dsh project folder (--<project>--) is read as a DeepSeek Harness log, the newest generation only; any other *.jsonl file is read as a Claude Code transcript. dsh keeps its sessions in $DSH_HOME/sessions, ~/.dsh/sessions by default. An opencode.db or opencode-<channel>.db is read as OpenCode’s database, each session in it on its own, and the folders below it are not walked; OpenCode keeps it in $XDG_DATA_HOME/opencode, ~/.local/share/opencode by default, which a new configuration lists instead when XDG_DATA_HOME is set. A session.jsonl in <YYYY>/<MM>/<DD>/<session id>/ is read as a Muse Code log; Muse keeps them in $XDG_DATA_HOME/muse/sessions, ~/.local/share/muse/sessions by default, listed the same way. A <session id>.jsonl in a project folder of a .commandcode/projects folder is read as a Command Code session (and no file under .commandcode as a Claude Code transcript); Command Code keeps them in ~/.commandcode/projects.
model_commandlist of stringsthe claude command belowThe command hippo runs for dreaming and for the reviewer. Each element {system_prompt} is replaced by the system prompt. The user prompt is written to the command’s standard input.
ingest_interval_minutesinteger, at least 110Minutes between scheduled ingests. Read by hippo schedule install, and by hippo doctor to decide when the index is stale (older than three intervals).
dream_atstring HH:MM"03:30"The time of day the scheduled dreaming run starts, on a 24-hour clock. Read by hippo schedule install.
reviewer_command_overridelist of stringsunsetAdvanced. A command to run the reviewer with instead of model_command. It follows the same rules. init does not write it. It exists for testing with a stand-in model, and it lets the reviewer run a different command from the proposing run.

After you change ingest_interval_minutes or dream_at, run hippo schedule install again. The values are written into the launchd job files (or the printed cron and systemd lines) when you install.

The default model command

model_command = [
  "claude", "-p", "--no-session-persistence", "--setting-sources", "", "--tools", "",
  "--strict-mcp-config", "--system-prompt", "{system_prompt}", "--output-format", "json",
]

This runs Claude Code in print mode with no tools, no settings files, no MCP servers and no saved session, so the model sees only what hippo sends. A replacement command must:

  • read the user prompt from standard input;
  • print one JSON object whose result field is the model’s reply, as claude -p --output-format json does;
  • finish within 600 seconds. After that hippo stops it and counts a model error.

hippo runs the command in $HIPPO_HOME/model-runs/, which it empties before every run.

Set it with hippo config set model_command '<JSON array>' --yes, for example '["my-model","--json"]', or with words separated by spaces. hippo writes the key as a one-line array and replaces a multi-line array whole. hippo config unset model_command --yes restores the default.

When the command exits non-zero, hippo shows its reason: the result of the JSON it printed (such as Not logged in · Please run /login), else the first non-empty line of stderr, else of stdout. When the program is not on PATH, the error says so.

<workspace>/.hippo/hippo.toml

Paths in this file are relative to the workspace, must not be absolute and must not contain ...

hippo init writes log_path out in full as "<notes_dir>/Session log.md" using the directory you gave.
